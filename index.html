🔐 Seeing his private repos too

Everything above comes from the public GitHub API — no login needed. GitHub profiles don't expose private repo counts or contents to anyone but the owner (or someone they've explicitly granted access to), and Azure CLI (az login) authenticates you to Azure, not GitHub — it won't unlock anything here. To extend this analysis to private repos, it has to be run by Erdem himself, authenticated as him:

🖥️  terminal — run as the account owner
1

Install & authenticate the GitHub CLI

brew install gh then gh auth login — choose GitHub.com, HTTPS, and log in via browser. This is the GitHub equivalent of az login; Azure's CLI has no visibility into GitHub.com repos.

2

Grant the right scope

Run gh auth refresh -h github.com -s repo to add the repo scope (or generate a fine-grained personal access token under Settings → Developer settings → Personal access tokens with Contents: Read on private repos).

3

Pull the full repo list, private included

gh repo list rifaterdemsahin --limit 500 --json name,description,visibility,pushedAt,languages,stargazerCount — the authenticated call returns private and internal repos alongside public ones; the anonymous API call used for this report cannot.

4

Re-run this analysis

Feed that JSON through the same categorisation pass used here (keyword match on name/description/topics) to fold private repos into the language, category and timeline charts above.

🔒 Why not just try harder: there is no key, header or workaround that surfaces someone else's private repos from outside their account — that's GitHub's access model working as intended, not a gap in this report.
